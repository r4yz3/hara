# ADR-003: ULID identifiers

- Status: accepted; letter case to be confirmed in Sprint 3
- Date: 2026-11-12

## Context
The master plan allows UUID or ULID. The spec chooses ULID and requires one type throughout.

## Decision
- Every domain table uses a ULID primary key stored as `char(26)`, generated by Laravel's `HasUlids`. Foreign keys are `char(26)` with explicit constraints.
- Tables supplied by Laravel or first-party packages (migrations, jobs, cache, sessions, `personal_access_tokens`) keep their generated key types. They are not redefined.
- IDs are opaque strings in the API. Clients never parse them for time ordering.
- One letter case is stored. Sprint 3 confirms which case the installed framework emits and adds a test. Route binding normalizes incoming IDs to that case, so a differently cased ID resolves to the same record or to 404, never to a second record.
- IDs are not secrets. Authorization never depends on an ID being hard to guess.

## Consequences
- Sortable keys keep index locality without exposing sequential counts.
- Polymorphic references (`user_role_scopes.scope_id`, `audit_logs.subject_id`) share one column type but cannot have foreign keys; their validity is checked in the service layer and tested.
