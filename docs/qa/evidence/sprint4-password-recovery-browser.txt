Password recovery: end-to-end run against the real stack
Date: 2026-11-13. Customer app http://localhost:3000 (next dev), API in Docker, email captured by Mailpit.
Account: a throwaway synthetic account created for this run and deleted afterwards.

1. Sign-in page -> "Forgotten your password?" -> /forgot-password. Entered the account's email, pressed Send.
   Page: "If that address has an account, we have sent it a link to choose a new password. The link works once
   and expires in an hour."
2. Mailpit held 1 message: to the account, subject "Reset your password", plain text only.
   Link shape: http://localhost:3000/reset-password#token=<64 hex chars>. No email address and no query string in it.
3. Opened the link. The address bar became http://localhost:3000/reset-password (token removed).
   BUG FOUND on the first attempt: the page said it needed a link. In development React runs effects twice; the
   second run found the fragment already cleared. Fixed by reading the token exactly once. Re-run: the form appeared.
4. Mismatched confirmation: "The two passwords do not match." Nothing sent.
5. Matching passwords: "Your password has been changed. Sign in with the new one."
6. Afterwards, by direct requests: 0 reset tokens left in the database; 1 audit entry auth.password_reset;
   the same link used again -> 422; sign-in with the new password -> 200.
7. Cleanup: throwaway account deleted, captured email deleted.

Not covered: the admin and merchant apps' copies of these pages (same components), an expired link in the browser,
the three-emails-per-15-minutes limit in the browser, keyboard-only use, a screen reader, a real mail provider.
