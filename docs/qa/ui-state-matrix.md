# UI state matrix (backlog U-03)

Spec: `FOOD_DELIVERY_PHASE1_IMPLEMENTATION.md` section 8.7 (states) and 8.8 (accessibility).
Tests: `tests/browser/state-matrix.spec.ts` (this item), `tests/browser/customer.spec.ts` (the customer account, cited as `account:`) and `tests/browser/phase1.spec.ts` (earlier items, cited as `phase1`). Server-rendered states are in `tests/browser/server-fetch-states.spec.ts` (cited as `banner:`, `api row:`) and app-level error screens in `tests/browser/error-states.spec.ts` (`errors:`).
Every test runs in the phone (375), tablet (768) and desktop (1440) projects. The API is replaced by route
interception, so no real data, account or position is involved. Sign-in, forgot-password and reset-password pages are
not in this matrix (they are being changed separately).

## How to read a cell

- `covered (test)`: a browser test forces the state and asserts what the user sees. Tests that start with a view name
  (`cities:`, `city:`, `exclusions:`, `audit:`, `settings:`, `location:`, `access:`) are in `state-matrix.spec.ts`; `account:` tests are in `tests/browser/customer.spec.ts`.
- `n/a (reason)`: the view cannot reach the state.
- `gap (reason)`: reachable, not proven by a test, or not built.

Where a view shows an error, it names what happened (`describeFailure` in `packages/session`) and keeps entered data.
Axe (WCAG 2.2 AA tags, plus a no-horizontal-scroll check) runs in the forbidden and error states of the admin
cities, city, audit and settings views, the location view's validation and offline states, and the admin overview. It also runs on the admin access view (loaded, empty, error and grant-form states) and the customer account view (loaded and error states).

## Changes made to close gaps

- Admin: loading indicators are now `role="status"` (announced), on `/cities`, `/cities/[id]` and `/audit`.
- Admin: a server-refused value (422) now moves focus to the first refused field and sets `aria-invalid` on city
  create, city edit, zone create; focus moves for zone edit and exclusion add. An unparsable GeoJSON entry focuses the
  shape field.
- Admin: after a 409 on a city or zone change, the message is followed by a "Reload latest" button. Before, a zone
  conflict reloaded silently and the explanation was lost when the row was replaced.
- Admin audit: Apply ignores a second press while the list loads (`aria-disabled`, so focus stays on the button).
- Customer: a server-refused position on `/location` focuses the field it names.

## Gaps left, with reasons

- G1. Offline cached read with a stale timestamp (spec 8.7 offline). Not built for any view: it needs a service worker or
  client cache, which is a design decision (data retention on shared staff devices, cache invalidation after 403 or
  sign-out). Today an offline view keeps what is on screen, says the connection was lost, keeps entered data and
  offers a retry; that behaviour is what the offline cells above prove.
- G2. Closed 2026-11-14: server-rendered states (customer `/` banner, admin `/` API row) are now tested. The stand-in API (`tests/browser/public-config-server.mjs`) takes `POST /__mode` to answer ok, open, error (500), garbage, slow (1.2 s), hang (never) or drop (socket closed, as a dead port does). The admin dev server now also gets `API_URL` pointing at it. Because those tests change a shared stand-in, `tests/browser/server-fetch-states.spec.ts` runs in three chained projects (`phone-server-fetch`, `tablet-server-fetch`, `desktop-server-fetch`) after the other projects; use `--no-deps` to run only them. Not in `BROWSER_LIVE=1` runs.
- G3. Success feedback is an inline `role="status"` message plus a refreshed list, not a toast. There is no toast
  component yet (backlog U-02 lists one for `packages/ui`).
- G4. Closed 2026-11-14: every app has `app/error.tsx`, `app/global-error.tsx` and `app/not-found.tsx`, built from `ErrorScreen` and `NotFoundScreen` in `packages/ui/src/problem-page.tsx`. They show plain words, "Try again" (the framework's `retry()`; this Next.js version prefers it to `reset()`) and a link home, and never the error message or stack; only the first 8 characters of the digest, when alphanumeric, are shown as "Reference". The throwing routes `/test-faults/[kind]` (each app) return not found in a production build. G4a (open): `global-error.tsx` (a failing root layout) is built and type-checked, but no browser test reaches it, because nothing in the apps can make the root layout throw without a test hook in the layout itself; a manual attempt in the dev server showed the framework's development overlay, not our screen. A production-mode check is still owed.
- G5. The Next.js development overlay badge can sit over bottom-left controls on a phone and intercept pointer
  clicks in the dev server; the audit offline test uses keyboard activation for that reason. It does not exist in a
  production build.
- G6. Closed 2026-11-14: `/account` on a 403 now offers a "Back to home" link (no Retry, since a refusal does not change on retry); test "account: a refused account says so and leads back to the home page".
- G7. Closed 2026-11-14: test "account: a slow sign-out disables the button and a second press sends nothing" holds the logout request and proves one request only.

## Accessibility notes (spec 8.8)

Errors use `role="alert"`, progress uses `role="status"` or `aria-busy`, refused fields carry `aria-invalid`, and
every action stays reachable by keyboard. Colour pairs are the ones listed in `docs/ux/contrast-report.md`; no new
colour was added.
