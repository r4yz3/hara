# Map tiles on staging: hosting runbook (ADR-015, backlog U-04 and U-10)

Status on 2026-11-14: **written, not run.** Nothing below has been executed against Cloudflare or a real extract. The style generator (`infra/map/build-style.mjs`) was run on the workstation against the pinned packages with a synthetic tile host, and the style's fonts and icon names were checked against the pinned assets (section 2). The size and cache figures are estimates and are marked as such.

**Hard rule:** the launch area (Magsaysay, Bansalan and Matanao, Davao del Sur) is named in prose only. The bounding box, any coordinates and any map centre never go into a tracked file, a commit message, an issue, chat or this document. You type the bounding box into your own PowerShell session (section 4); the extract file and the style stay on your PC and in R2.

Budget: everything here fits the Cloudflare free tier (no Workers, no paid plan). Prices and limits are from Cloudflare's pages read on 2026-11-14; check them again before relying on them.

## 1. Layout

```
Browser (staging-admin / staging / staging-merchant)
   |  1. GET /api/v1/public/config  ->  map_style_url      (staging-api, from MAP_STYLE_URL in the server .env)
   |  2. GET https://tiles.haradelivery.com/style-<DATE>.json
   |  3. GET .../sprites/v4/light(.json|.png|@2x...)       and  .../fonts/<font>/<range>.pbf
   |  4. GET .../hara-staging-<DATE>.pmtiles  with  Range: bytes=a-b      (many small requests)
   v
Cloudflare (zone haradelivery.com, proxied, Universal SSL) --> R2 bucket hara-staging-tiles  (public via custom domain only)
```

| Item | Choice | Why |
|---|---|---|
| Bucket | `hara-staging-tiles`, **separate** from the private `hara-staging-backups` | Backups stay private; the tile bucket holds only public data |
| Public access | Custom domain `tiles.haradelivery.com` only. Leave `r2.dev` **disabled** | `r2.dev` is rate limited, uncached and has no CORS control. A one-level subdomain is covered by the free Universal certificate (`*.haradelivery.com`) |
| Worker | None | R2 serves byte ranges itself. Protomaps' optional Worker would add a paid-plan dependency for nothing we need |
| Files | `hara-staging-<DATE>.pmtiles`, `style-<DATE>.json`, `fonts/`, `sprites/v4/` | Dated names are immutable: a new extract is a new file and a new style, so no browser or edge cache can mix old and new bytes. Delete old dates after the switch |
| CORS | `GET`, `HEAD`, header `range`, from the three web origins only; exposes `Content-Range`, `ETag`, `Content-Length`, `Accept-Ranges` | Section 6. PMTiles reads `ETag` and `Content-Range` to detect a replaced file (it deliberately sends no `If-Match`, so no preflight is needed) |
| Cache | One Cache Rule on the tiles host (section 6, step 5) | `.pmtiles`, `.json` and `.pbf` are **not** cached by Cloudflare by default |

Range requests and caching, with caveats:

- R2 answers `Range` natively (`206`, `Content-Range`, `Accept-Ranges: bytes`), with or without the Cloudflare cache in front. Egress is free, so a cache miss costs only a Class B read operation (10 million a month are free; one tile is roughly one read). Caching is an optimisation here, not a requirement.
- Cloudflare can serve ranges from a fully cached object. The free plan caches objects up to 512 MB; a larger `.pmtiles` is simply served from R2 every time (still correct). Whether a *first* range request fills the cache is not documented in the pages read; **check `cf-cache-status` in section 8** and do not rely on it.
- Do not let anything compress the `.pmtiles`: `Content-Encoding` must be absent in the test, and the `ETag` must not start with `W/` (PMTiles ignores weak ETags).
- "Purge Everything" clears the whole zone, so after changing CORS purge only the tiles hostname (Caching > Configuration > Custom Purge > Hostname).

## 2. What the map needs besides the `.pmtiles`

| Piece | Source (pinned) | Hosted as |
|---|---|---|
| Vector tiles | Protomaps daily build of OpenStreetMap data, `https://build.protomaps.com/<YYYYMMDD>.pmtiles` (the builds of 2026-11-10 to 2026-11-14 exist; each is about 139 GB, so you never download it whole, `extract` reads only the ranges it needs). Pin the date you extract from and record it in `PHASE1_STATUS.md` | `hara-staging-<DATE>.pmtiles` |
| Extractor | `go-pmtiles` **v1.31.2** (release of 2026-07-22), Windows x86_64 zip. SHA-256 from the GitHub release API: `a658baa4d7e55020aef6ca17bd9ff9faa1582671266b36f58c52db0ac8e785a1` | your PC only |
| Style | `@protomaps/basemaps` **5.7.2** (npm, 2026-03-10, BSD-3-Clause, no dependencies), flavor `light`, `lang` `en`. Generated by `infra/map/build-style.mjs` into a static JSON, 71 layers, about 66 KB, **no centre, zoom or bounds** | `style-<DATE>.json` |
| Glyphs (fonts) | `protomaps/basemaps-assets` at commit `028c18f713baecad011301ff7a69acc39bcc2ae7` (2025-10-31; the repository has no releases, so the commit is the pin). `fonts/`: Noto Sans Regular, Medium, Italic, about 12 MB in 768 files, SIL OFL 1.1 (`fonts/OFL.txt` is uploaded with them) | `fonts/` |
| Sprites | Same commit, `sprites/v4/` (about 184 KB, derived from MIT-licensed tangrams/icons) | `sprites/v4/` |
| Attribution | In the style source: "© OpenStreetMap contributors" (links to the OSM copyright page) and "Protomaps". MapLibre's attribution control prints it, bottom right, always (the component creates it with `compact: false`). OSM data is ODbL | inside `style-<DATE>.json` |

Self-hosting glyphs and sprites in the same bucket means no runtime dependency on `protomaps.github.io` or any other third party. The style lists fonts "Noto Sans Regular/Medium/Italic" only; the check on 2026-11-14 found every font name and the one literal `icon-image` in the style present in the pinned assets (the other icon names come from expressions over tile attributes and are resolved at run time).

The map component needs no change for any of this: it receives the style URL from `GET /api/v1/public/config` (`map_style_url`), registers the `pmtiles://` protocol and fits the view to the zone shape. It sets no centre. The style is generated at **operator time** with `npm install` into a scratch folder (network once), then `node` runs offline. It is not generated at web build time, and no dependency was added to the workspace.

## 3. Prerequisites (PowerShell on your PC; Git and Node.js are already installed for the repo)

Use a working folder outside the repository. Everything in it is untracked and may contain your bounding box in the `.pmtiles` header:

```powershell
$work = "$HOME\hara-tiles"; New-Item -ItemType Directory -Force $work | Out-Null; Set-Location $work
```

Download the pinned CLI (about 10 MB, from the go-pmtiles GitHub release):

```powershell
Invoke-WebRequest "https://github.com/protomaps/go-pmtiles/releases/download/v1.31.2/go-pmtiles_1.31.2_Windows_x86_64.zip" -OutFile go-pmtiles.zip
```

The next command must print `True`:

```powershell
(Get-FileHash go-pmtiles.zip -Algorithm SHA256).Hash.ToLower() -eq "a658baa4d7e55020aef6ca17bd9ff9faa1582671266b36f58c52db0ac8e785a1"
```

```powershell
Expand-Archive go-pmtiles.zip -DestinationPath cli -Force; .\cli\pmtiles.exe version
```

It must print `1.31.2`. If the hash is `False`, delete the zip and stop.

Install the style package into the scratch folder (not the repository), without running install scripts:

```powershell
npm install --prefix "$work\basemaps" @protomaps/basemaps@5.7.2 --ignore-scripts --no-audit --no-fund
```

Fetch the glyph and sprite sources at the pinned commit:

```powershell
git clone https://github.com/protomaps/basemaps-assets.git assets
```

```powershell
git -C assets checkout 028c18f713baecad011301ff7a69acc39bcc2ae7
```

```powershell
git -C assets rev-parse HEAD
```

It must print the commit id above.

## 4. Choose your bounding box (yourself, not written down)

1. Open `https://bboxfinder.com` (or the OpenStreetMap export page, `https://www.openstreetmap.org/export`, "Manually select a different area") and find Magsaysay, Bansalan and Matanao in Davao del Sur. Draw one rectangle around all three plus a margin of about 5 km on every side, so that a zone near a border and the surrounding roads are on the map.
2. Copy the box in `west,south,east,north` order, longitude first, decimal degrees (bboxfinder: "Box" with "lng/lat" selected).
3. Keep it in your session only. `Read-Host` input is not stored in the PowerShell history:

```powershell
$bbox = Read-Host "bbox west,south,east,north"
```

Do not paste the value into this repository, a commit message, chat or a ticket. A bigger box costs storage and download time (section 5); the PMTiles file records its own bounds, which is why the file is not committed either.

## 5. Extract, check, build the style

Pick the build date. Check that the build exists (expect `200` and a length of about 139 billion bytes):

```powershell
$date = "20261113"; curl.exe -sI "https://build.protomaps.com/$date.pmtiles" | Select-String "HTTP|content-length"
```

Dry run first. It lists the tile count and size without downloading the tiles. Flags checked against go-pmtiles v1.31.2 `main.go`: `--bbox`, `--minzoom`, `--maxzoom`, `--dry-run`, `--download-threads`, `--overfetch`.

```powershell
.\cli\pmtiles.exe extract "https://build.protomaps.com/$date.pmtiles" "hara-staging-$date.pmtiles" --bbox=$bbox --maxzoom=15 --dry-run
```

Expected size (**estimate, not measured**): roughly 30 to 400 MB for a rural box of this kind at `--maxzoom=15` (the planet is 139 GB). If the dry run says more than about 1 GB, the box is too large or wrong (west and east swapped?): stop. If it is large but right, use `--maxzoom=14`, which is a few times smaller; map zoom beyond 14 then overscales the last level. Then run it for real (the download needs the network for several minutes and is resumable by running it again):

```powershell
.\cli\pmtiles.exe extract "https://build.protomaps.com/$date.pmtiles" "hara-staging-$date.pmtiles" --bbox=$bbox --maxzoom=15
```

Verify the archive. `show` must report `tile type: mvt`, a max zoom of 15 and `clustered: true`; the vector layer list (`--metadata`) must include `water`, `roads`, `places`, `buildings`; `verify` must finish without error:

```powershell
.\cli\pmtiles.exe show "hara-staging-$date.pmtiles"
```

```powershell
.\cli\pmtiles.exe show "hara-staging-$date.pmtiles" --metadata | Select-String "water|roads|places|buildings" | Select-Object -First 4
```

```powershell
.\cli\pmtiles.exe verify "hara-staging-$date.pmtiles"
```

Record the file size: `(Get-Item "hara-staging-$date.pmtiles").Length`. Do not copy the bounds line of `show` anywhere.

Generate the style (offline from here; uses the checked-out repository only for the script):

```powershell
node F:\PROJECTS\hara\infra\map\build-style.mjs --basemaps "$work\basemaps\node_modules\@protomaps\basemaps\dist\esm\index.js" --tiles-origin https://tiles.haradelivery.com --pmtiles "hara-staging-$date.pmtiles" --out "style-$date.json"
```

It prints `wrote style-<date>.json: 71 layers`. Options: `--flavor` (`light` default, `dark`, `white`, `black`, `grayscale`; the zone overlay is blue and red, so `light` or `white` read best) and `--lang`.

## 6. Cloudflare (dashboard)

1. **R2 object storage > Create bucket**: name `hara-staging-tiles`, location hint Asia-Pacific if offered. Leave "Public Development URL" (`r2.dev`) **disabled**.
2. **Bucket > Settings > Custom Domains > Connect Domain**: `tiles.haradelivery.com` (the zone is yours; Cloudflare creates the proxied DNS record and the certificate is the zone's Universal certificate). Wait until the status is Active.
3. **Bucket > Settings > CORS Policy > Add CORS policy > JSON**, paste exactly:

```json
[
  {
    "AllowedOrigins": [
      "https://staging.haradelivery.com",
      "https://staging-merchant.haradelivery.com",
      "https://staging-admin.haradelivery.com"
    ],
    "AllowedMethods": ["GET", "HEAD"],
    "AllowedHeaders": ["range"],
    "ExposeHeaders": ["Content-Range", "Content-Length", "ETag", "Accept-Ranges"],
    "MaxAgeSeconds": 3600
  }
]
```

   No `localhost` origin is allowed. To try the staging tiles from a local dev server you would add `http://localhost:3002` yourself, as a separate decision.
4. **R2 > Manage API tokens > Create API token** for uploads: permission **Object Read & Write**, **Specify bucket**: `hara-staging-tiles` only. Copy the Access Key ID, Secret Access Key and the S3 endpoint (`https://<ACCOUNT_ID>.r2.cloudflarestorage.com`) into your password manager. This is a different token from the backups one. Delete it (or let it expire) after the upload.
5. **Caching > Cache Rules > Create rule**, name "tiles": when *Hostname equals* `tiles.haradelivery.com`, then *Cache eligibility: Eligible for cache*, *Edge TTL: Use cache-control header if present, bypass cache if not*, *Browser TTL: Respect origin*. Without this rule the files are served uncached (still correct, see section 1).

## 7. Upload

The dashboard upload is limited to 300 MB per file, so use `rclone` (also handles the 768 font files):

```powershell
winget install --id Rclone.Rclone -e
```

Open a new PowerShell window afterwards so `rclone` is on the path, `Set-Location "$HOME\hara-tiles"`, and set the date again (`$date = "20261113"`). Configure a remote through environment variables of this session only (nothing is written to disk; the secret is read without echo):

```powershell
$env:RCLONE_CONFIG_TILES_TYPE = "s3"; $env:RCLONE_CONFIG_TILES_PROVIDER = "Cloudflare"; $env:RCLONE_CONFIG_TILES_NO_CHECK_BUCKET = "true"; $env:RCLONE_CONFIG_TILES_ACCESS_KEY_ID = Read-Host "Access Key ID"; $env:RCLONE_CONFIG_TILES_ENDPOINT = Read-Host "S3 endpoint"
```

```powershell
$env:RCLONE_CONFIG_TILES_SECRET_ACCESS_KEY = [System.Net.NetworkCredential]::new("", (Read-Host "Secret Access Key" -AsSecureString)).Password
```

The archive (immutable, a year of cache):

```powershell
rclone copyto "hara-staging-$date.pmtiles" "tiles:hara-staging-tiles/hara-staging-$date.pmtiles" --header-upload "Cache-Control: public, max-age=31536000, immutable" --progress
```

Fonts and sprites (immutable for the pinned commit):

```powershell
rclone copy assets\fonts tiles:hara-staging-tiles/fonts --header-upload "Cache-Control: public, max-age=31536000, immutable" --exclude ".git/**" --transfers 16
```

```powershell
rclone copy assets\sprites\v4 tiles:hara-staging-tiles/sprites/v4 --header-upload "Cache-Control: public, max-age=31536000, immutable"
```

The style last, with a short cache so a rollback is quick:

```powershell
rclone copyto "style-$date.json" "tiles:hara-staging-tiles/style-$date.json" --header-upload "Cache-Control: public, max-age=300" --header-upload "Content-Type: application/json"
```

```powershell
rclone size tiles:hara-staging-tiles
```

Expect the archive size plus about 13 MB. This is far below the 10 GB-month free storage; keep only the current and the previous date. Clear the session variables when done:

```powershell
Get-ChildItem Env:RCLONE_CONFIG_TILES_* | Remove-Item
```

## 8. Test before touching the servers

Archive: a ranged read must give `206`, a `Content-Range` ending in the file size, `Accept-Ranges: bytes`, the CORS headers for an allowed origin, and no `Content-Encoding`:

```powershell
curl.exe -sS -D - -o NUL -H "Range: bytes=0-16383" -H "Origin: https://staging-admin.haradelivery.com" "https://tiles.haradelivery.com/hara-staging-$date.pmtiles"
```

Look for: `HTTP/1.1 206`, `Content-Range: bytes 0-16383/<size>`, `Accept-Ranges: bytes`, `Access-Control-Allow-Origin: https://staging-admin.haradelivery.com`, `Access-Control-Expose-Headers` listing `Content-Range`, `ETag` and the rest, an `ETag` that does not start with `W/`, and no `Content-Encoding`. `cf-cache-status` may say `MISS`, `DYNAMIC` or `HIT`; run the command twice and note the second value in the status file (section 1: caching is optional).

The file is a PMTiles archive (the first seven bytes are the magic string):

```powershell
curl.exe -s -H "Range: bytes=0-6" "https://tiles.haradelivery.com/hara-staging-$date.pmtiles"
```

It prints `PMTiles`.

Other origins get no CORS header (the line must be absent):

```powershell
curl.exe -sS -D - -o NUL -H "Range: bytes=0-6" -H "Origin: https://example.com" "https://tiles.haradelivery.com/hara-staging-$date.pmtiles" | Select-String "access-control"
```

The style, a glyph range and a sprite (each `200`, the first with `application/json`):

```powershell
curl.exe -sSI -H "Origin: https://staging-admin.haradelivery.com" "https://tiles.haradelivery.com/style-$date.json"
```

```powershell
curl.exe -sSI "https://tiles.haradelivery.com/fonts/Noto%20Sans%20Regular/0-255.pbf"
```

```powershell
curl.exe -sSI "https://tiles.haradelivery.com/sprites/v4/light.json"
```

The bucket must not be reachable through `r2.dev` (the Public Development URL stays off).

## 9. Switch staging on

On the server, in `/srv/hara/infra/staging/.env`, set one line (open the file yourself; the value is a public URL, not a secret):

```
MAP_STYLE_URL=https://tiles.haradelivery.com/style-<DATE>.json
```

The style URL is read at **run time** by the API (`GET /api/v1/public/config`, which returns it only if it is an https URL), so **no web image rebuild is needed**. The API caches its configuration at container start (`config:cache` in the entrypoint), so recreate the API container:

```bash
cd /srv/hara/infra/staging && docker compose up -d --force-recreate --wait api
```

```bash
curl -sk --resolve staging-api.haradelivery.com:443:127.0.0.1 https://staging-api.haradelivery.com/api/v1/public/config
```

`map_style_url` must show the new URL. Then, in the staging admin app, open a city and its zone form: the map must draw, with the attribution "OpenStreetMap contributors" and "Protomaps" bottom right, and no request must fail in the browser's network tab (a font 404 only falls back to a system font, but should still be fixed). Drawing a zone is done by hand on the real map; the map opens fitted to a zone's shape only, and has no position before one exists.

`NEXT_PUBLIC_MAP_STYLE_URL` stays empty in `.env`. It is only read by the Content Security Policy helper (`tileOriginFrom` in `packages/config/security-headers.mjs`), which is not wired into the apps yet (E-02, deferred); today the apps send only the static baseline policy, which does not restrict connections, images, fonts or workers. **When the per-request policy is wired**, set `NEXT_PUBLIC_MAP_STYLE_URL` to the same URL and rebuild the three web images with `--build-arg NEXT_PUBLIC_MAP_STYLE_URL=...` (the Dockerfile already has the argument). The helper then adds `https://tiles.haradelivery.com` to `connect-src`, which covers the style, glyphs, sprites and range reads (MapLibre fetches all of them); `worker-src 'self'` covers its bundled worker. `img-src` is not needed for the sprite PNG (fetched as bytes), but test it with the real policy in Playwright when E-02 lands.

## 10. Rollback and refresh

- **Back to the placeholder:** empty `MAP_STYLE_URL=` and repeat the `--force-recreate` command. The map shows "Map not configured" and every form still works through the GeoJSON field.
- **Back to the previous extract:** set `MAP_STYLE_URL` to the previous `style-<DATE>.json` (kept in the bucket) and recreate the API.
- **Refresh the data:** repeat sections 4 (reuse `$bbox` from your notes, not from the repository), 5, 7 (new dated files), 9. Then delete the old dated files with `rclone delete`.

## 11. What stays unverified until you run it

The extract size, `pmtiles extract` against the chosen build, Cloudflare's range and cache behaviour on the custom domain, the rclone upload, the CORS policy, and the map drawing in the real admin app. Record the dates, the build date, the file size and the curl results in `docs/PHASE1_STATUS.md` once done. Nothing here proves a launch-city choice: the tiles show where OpenStreetMap has data and say nothing about service coverage.
